# VOICEPEAK の常駐制御

Linux x86_64 / glibc の検証済み VOICEPEAK では、moca-server が起動した
1 個のプロセスと合成 runtime を要求間で保持する。文章・話者・速度・高さ・感情は
要求ごとに渡し、通常の合成処理から別々の一時 WAV へ書き出す。
GUI 操作や音声再生の録音は使用しない。

## 対応版と切り戻し

- VOICEPEAK 1.2.21 Linux x86_64。
- ELF build ID: `65a2effbee1d5d908a735d1b66b4aaad2071bbc4`。
- 検証した実行ファイルの SHA-256: `691a6e6ffe01bca9ddb5b742999b7a5192b072cd296a2c890451cbcb2941b670`。
- Windows、macOS、その他の Linux 版・ビルドでは従来の CLI 都度起動を継続する。
- `MOCA_VOICEPEAK_RESIDENT=0` を設定し moca-server を再起動すれば、対応版でも都度起動へ戻る。

対応版では moca-server の更新・再起動後、最初の合成時から自動で有効になる。
別の daemon や GUI 起動、VOICEPEAK 本体の変更は不要。
ログの `VOICEPEAK resident started` に所有 PID を記録する。
起動時に常駐制御が成立しなければ、そのサーバープロセスでは CLI に切り替えて再試行する。

通常の VOICEPEAK インストールとアクティベーションは必要。
同時実行制限・ライセンス検証・引数の検証は VOICEPEAK の元の処理を通す。
常駐中は CLI インスタンスを保持するため、別の CLI 利用との同時実行には従来と同じ制限がある。
配布するのは自作の制御コードだけで、本体・音源・認証情報は含めない。
非公開の内部関数を利用しており、メーカーの公式 API 対応や許諾取得を表すものではない。

## 実装と出力

`native/voicepeak_resident.cpp` の共有ライブラリを moca-server バイナリに埋め込む。
所有する子プロセスだけへ `LD_PRELOAD` で渡す。ディスク上の VOICEPEAK は書き換えない。
ELF build ID と対象関数の先頭命令を確認してから、プロセス内の呼び出しを差し替える。
対象版の `cliDoCommandLine` と `ensureRuntimeObject` を呼び、初期化済み runtime を保持する。
要求は VOICEPEAK の message thread へ渡す。待機中も本来の event loop は動く。

親子間は標準入力の長さ付き引数列と専用の完了通知を使う。内部関数の完了通知は
成功コードではないため、親が新しい WAV の RIFF サイズと PCM を確認してから返す。
stdout の通常ログは stderr へ移し、制御の応答と混ぜない。

出力は従来どおり `NamedTempFile`。`/tmp` が tmpfs の環境では WAV もメモリ上に置かれる。
独自 RAM ディスクは作らず、処理終了時に削除する。WAV/Opus 配信とポーズの挿入は既存経路を共有する。

要求は既存の FIFO mutex で直列化する。1 文節の制限時間は 60 秒。
合成中のクライアント切断・時間切れ・異常終了・不完全出力では所有する子を終了し、
次の試行で起動し直す。正常終了した子だけを次の要求に引き継ぐ。
他の VOICEPEAK プロセスを検索して終了する処理は持たない。

## 実機確認

通常サービスとは別のポート・一時 DB で moca-server を起動し、
`MOCA_VOICEPEAK_RESIDENT=0` の都度起動と、対応版の常駐方式を順番に比較する。
初回要求とウォームアップ後を分け、HTTP 要求開始から本文全体の受信までを測る。
同じ入力を各 3 回以上生成し、中央値・音声長・PCM の一致・子 PID と起動回数を確認する。

短文 2 種、読点で 2/4/8 回連結した文、4 文節の JSON 台本を比較対象とする。
速度・高さ・感情を変えた要求の直後に既定設定へ戻し、辞書、保存済み台本、ポーズ、
Opus も確認する。さらに所有子の強制終了、生成失敗、合成中の切断から復旧することを確かめる。

2026-09-17 の検証済み版による実測（各 3 回の中央値、秒、初回要求を除外）:

| 入力 | CLI 都度起動 | 常駐 | 比率 |
| --- | ---: | ---: | ---: |
| 雨が降っています | 1.352 | 0.294 | 4.60倍 |
| 今日は家で調べ物をします | 1.503 | 0.430 | 3.49倍 |
| 後者を読点で2回連結 | 1.997 | 0.868 | 2.30倍 |
| 同4回連結 | 3.026 | 1.993 | 1.52倍 |
| 同8回連結 | 5.371 | 4.066 | 1.32倍 |
| 後者を4文節のJSON台本にする | 6.224 | 1.736 | 3.59倍 |

初回要求は CLI 1.407 秒、常駐 1.252 秒。比較区間は初回を含め 28 文節で、
起動回数は CLI 29 回、常駐 2 回だった。両方式とも途中で 1 回異常終了し、再試行で成功した。
同様の比較を 2 回行い、全比較音声と設定変更・既定値への復帰の PCM は両方式で一致した。
設定・既存経路の確認区間にも同種の異常終了があった。
採取できた 6 件のクラッシュは、すべて本体の同じ命令位置だった。
原因は未確定であり、常駐方式が異常終了を解消したとは扱わない。
上表の時間には発生した再試行を含めており、失敗試行を取り除いた成績ではない。
